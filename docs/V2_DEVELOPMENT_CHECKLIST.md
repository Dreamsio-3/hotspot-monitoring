# 第二版开发清单：多来源增量监控与热点雷达收敛

> 版本：V2
> 规划日期：2026-09-27
> 基线：V1 GitHub 热点监控已完成
> 状态：开发规划

本文将第二版需求拆解为开发任务、接口约定、数据变更和验收标准。附图中的“搜索”导航及搜索表单仅作为当前界面状态参考；本版按需求将其从用户流程中移除。

## 1. 版本目标

第二版将产品从“监控词 + 手动搜索”收敛为“启用监控词 + 定时增量扫描 + 热点雷达”。扫描任务需要同时覆盖 Bing、Google、搜狗和微博，并继续兼容 V1 已有的 Twitter、GitHub、Hacker News、Bilibili 等来源。

用户只需要维护监控词并开启需要追踪的词，系统就会按计划扫描各来源，将新内容增量写入数据库、进行 AI 分析、推送通知并展示在热点雷达中。停用监控词后，相关历史内容保留，但不再出现在热点雷达的默认列表中。

### 2.1 本版明确的解释

- “搜索来源”指后台定时扫描使用的数据源，不代表继续保留一个供用户临时输入的搜索页。
- Bing、搜狗、微博的服务函数目前已有，V2 需要把它们纳入统一的扫描策略、增量状态、错误观测和验收；Google 服务函数已有，但当前未进入 `runHotspotCheck`，需要接入并验证解析稳定性。
- 现有“立即扫描”属于任务控制能力，可以保留并改为触发一次完整的增量扫描，不恢复“搜索”页面。
- 停用关键词不做物理删除，也不自动删除已经产生的热点和通知；默认热点雷达只展示当前仍启用关键词关联的内容。

## 3. 当前代码基线

- `server/src/jobs/hotspotChecker.ts` 已按 `isActive: true` 读取关键词，但采集任务固定由 `server/src/index.ts` 每 30 分钟触发，缺少持久化的运行状态和每个关键词的扫描水位。
- `server/src/services/search.ts` 已包含 `searchBing` 和 `searchGoogle`；`server/src/services/chinaSearch.ts` 已包含 `searchSogou` 和 `searchWeibo`。
- 当前定时扫描已经调用 Bing、搜狗和微博，但未调用 Google；四个来源还没有统一的单来源增量状态。
- `server/src/routes/hotspots.ts` 仍提供 `POST /api/hotspots/search`，前端 `client/src/App.tsx` 仍有“搜索”导航、表单和结果列表。
- `Keyword` 已有 `isActive`；`Hotspot` 通过 `keywordId` 关联监控词，适合增加状态过滤和增量关联。
- V1 已有来源、AI 分析、数据库去重、WebSocket、邮件和 GitHub 字段，本版应复用这些链路，避免建立第二套热点处理流程。

## 4. 后端开发清单

### 4.1 统一来源采集

- [ ] 定义 V2 默认监控来源集合：`twitter`、`bing`、`google`、`sogou`、`weibo`、`github`、`hackernews`、`bilibili`。
- [ ] 将各来源统一为 `Promise<SearchResult[]>` 适配器，保留来源、标题、正文、规范化 URL、来源 ID、发布时间和互动指标。
- [ ] 把 `searchGoogle(keyword)` 接入定时扫描；验证中文关键词、英文关键词、无结果、页面结构变化和验证码/限流响应。
- [ ] 复用 `searchBing`、`searchSogou`、`searchWeibo`，补齐请求超时、频率限制、User-Agent、解析失败和空结果处理。
- [ ] 每个来源独立执行，单个来源失败只记录该来源错误，不阻塞同一关键词的其它来源和其它关键词。
- [ ] 为来源设置单独配额和请求间隔，避免增加四个来源后触发搜索引擎封禁；将超时、限流和反爬结果写入任务日志。
- [ ] 保持 `deduplicateResults` 的 URL 规范化逻辑，并补充来源 ID 优先的稳定去重键。
- [ ] 对微博热搜这类榜单来源区分“首次发现”和“热度更新”，同一话题更新热度时不重复创建热点通知。

### 4.2 增量扫描任务

- [ ] 新增 `server/src/services/scheduler.ts`，负责任务配置读取、到期判断、互斥锁、运行状态更新和任务触发。
- [ ] 将固定的 `cron.schedule('*/30 * * * *')` 改为可配置调度；默认间隔仍为 30 分钟，允许的间隔至少覆盖 5、10、15、30、60 分钟。
- [ ] 调度器每次只读取 `Keyword.isActive = true` 的关键词；没有启用关键词时记录一次空运行并正常结束。
- [ ] 增加任务互斥锁或运行令牌，避免定时任务、立即扫描和上一次慢任务并发处理同一批关键词。
- [ ] 支持优雅停止和重启恢复；服务重启后根据持久化的下次运行时间重新判断是否需要补跑，不重复发送旧热点通知。
- [ ] 将来源采集、增量过滤、AI 分析、保存、通知拆成可复用的单关键词执行函数，手动触发和定时触发共用同一条链路。
- [ ] 扫描完成后记录成功、部分失败和失败状态，以及新增数量、更新数量、过滤数量和各来源耗时。

### 4.3 增量水位与去重

- [ ] 新增 `KeywordScanState` 模型，至少包含 `keywordId`、`source`、`lastStartedAt`、`lastSuccessAt`、`watermarkAt`、`lastResultCount`、`lastError` 和更新时间；对 `[keywordId, source]` 建唯一约束。
- [ ] 新增调度器状态模型或等价的 Setting 记录，保存 `enabled`、`intervalMinutes`、`lastRunAt`、`nextRunAt`、`lastRunStatus` 和 `lastRunError`。
- [ ] 为上述模型创建 Prisma migration，允许从旧数据库平滑升级；现有热点和关键词数据保持可读。
- [ ] 有发布时间的来源使用 `watermarkAt - overlapWindow` 作为查询起点，默认保留短暂重叠窗口以避免时钟和延迟造成漏采。
- [ ] 没有发布时间的搜索引擎结果使用规范化 URL、来源 ID 和数据库唯一约束去重；不因每次抓取顺序变化重复入库。
- [ ] 已存在热点只更新允许变化的指标、正文和发布时间；不得重新触发 AI 分析、WebSocket 新热点事件或邮件通知。
- [ ] 新热点必须带正确的 `keywordId`；同一内容被多个关键词命中时定义去重和归属规则，并在文档中固定下来。
- [ ] 任务失败时不推进对应来源的 `watermarkAt`，下次扫描可以重试未完成区间。
- [ ] 对重复 Release、重复微博话题和搜索结果 URL 编写回归测试。

### 4.4 热点雷达过滤

- [ ] 修改 `GET /api/hotspots` 的默认查询条件，加入 `keyword: { isActive: true }`；`keywordId` 指向已删除关键词或为空的历史记录默认不进入雷达。
- [ ] 让分页总数、来源统计、今日新增和重要热点统计使用同一启用关键词过滤条件，避免卡片数量和统计数字不一致。
- [ ] 保留单条热点详情和历史数据的内部读取能力；如果需要查看停用词历史，增加明确的管理参数或单独接口，不能让默认雷达绕过过滤。
- [ ] 关键词切换为停用后，前端刷新雷达并移除对应卡片；重新启用后只显示数据库中已有且满足其它筛选条件的内容。
- [ ] WebSocket 只向启用关键词房间推送新热点；客户端收到事件后再次检查关键词状态，避免停用瞬间仍显示内容。
- [ ] 对旧数据、删除关键词、停用关键词、跨关键词重复内容分别编写测试。

### 4.5 搜索功能下线

- [ ] 删除 `POST /api/hotspots/search` 路由及其请求参数、响应类型和相关动态导入。
- [ ] 删除客户端 `hotspotsApi.search`、`searchQuery`、`searchSources`、`searchResults`、搜索处理函数和搜索结果专用渲染逻辑。
- [ ] 保留 `server/src/services/search.ts` 和 `chinaSearch.ts` 中被定时扫描使用的来源函数，不要将“删除搜索功能”误解为删除数据源。
- [ ] 对已下线接口返回明确的 404/410 行为，并在 API 文档中标注不再支持；不保留一个隐式可用的旧搜索入口。
- [ ] 删除搜索路由、搜索聚合、手动搜索响应和搜索页相关测试；新增接口下线测试。

### 4.6 调度管理接口

- [ ] 新增 `GET /api/scheduler/status`，返回调度开关、间隔、运行状态、最近运行时间、下次运行时间、当前运行关键词数、上次统计和最近错误。
- [ ] 新增 `PUT /api/scheduler/config`，校验 `enabled` 和 `intervalMinutes`，保存后让调度器立即加载新配置。
- [ ] 保留或重构 `POST /api/check-hotspots` 为“立即执行一次增量扫描”，返回任务 ID/运行摘要，不允许启动并发任务。
- [ ] 可选新增 `GET /api/scheduler/runs` 查看最近任务记录；若本版不做历史页，至少保留最近一次状态和结构化日志。
- [ ] 接口响应不得返回 OpenRouter、GitHub 或其它来源的密钥。
